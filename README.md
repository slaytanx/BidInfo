# 입찰 수집·분류·문서 분석 시스템

최신 업데이트: 2026-10-13

국민은행, 농협 전체 입찰 게시판, 농협정보시스템의 공개 공고를 분야별로 수집하고 로컬 문서를 분석하는 Streamlit 앱입니다. 공고마다 원본 링크, 발주기관, 분야 태그, 추출·분석 상태, 제출 요건과 근거를 확인할 수 있습니다.

## 실행

기존 `.venv`를 재사용합니다.

```bash
.venv/bin/python -m streamlit run app.py
```

[로컬 페이지](http://localhost:8501)에서 수집 분야를 선택하고 날짜 범위를 지정한 뒤 수집을 시작합니다. 명백히 무관한 공고는 첨부를 받지 않습니다. 애매한 공고는 상세를 확인하고 필요하면 첨부를 읽습니다. 목록 조회 자체는 생략할 수 없습니다.

## 모델과 비용

- 기본: 로컬 `gemma4:e4b-mlx` 분류 → OpenRouter `deepseek/deepseek-v4-flash-0731` 분석.
- 로컬 전용·클라우드 실패 시: `gemma4:26b-mlx`.
- 비교 후보: `gemma4:12b-mlx`, `qwen3.8:fast`, `z-ai/glm-5.3-flash`, `upstage/solar-pro4`.
- 화면에서 처리 방식과 모델을 선택합니다. API 키가 없으면 로컬로 처리합니다.
- OpenRouter 키는 관리자 연결 설정, `OPENROUTER_API_KEY` 환경변수 또는 로컬 `.env`로 제공합니다. 화면에서 저장한 키는 권한 `0600`의 `.local_secrets.json`에만 보관하며 공고 DB·R2·Git에 포함하지 않습니다.
- 실행당 기본 예산은 미화 1달러입니다. 현재 모델 가격과 최대 출력량으로 진행 중 호출 비용을 예약합니다. 응답을 받지 못한 호출도 보수적으로 계산하며 예산 부족 시 로컬로 전환합니다. 화면 집계는 앱에서 실행한 텍스트 호출 범위이며 계정 전체의 지출 한도와 다릅니다.
- 공급자별 가격이 달라질 수 있어 [현재 모델 목록](https://openrouter.ai/api/v1/models)을 조회하고 허용 가격 상한을 요청에 포함합니다.

모델 비교는 운영 자료 대신 합성 한글 RFP 12건으로 수행합니다. 결과는 화면의 `모델 비교 결과`에서 확인합니다. 실제 RFP 정확도와 구분해야 하며 캐시가 있는 재실행 시간은 최초 추론 시간과 다를 수 있습니다.

```bash
.venv/bin/python benchmark.py --models gemma4:26b-mlx gemma4:12b-mlx qwen3.8:fast
```

## 문서와 분야

분야는 **인프라·보안·컨설팅·개발·기타**입니다. 분야 안의 서버·스토리지·방화벽·IPS 등 **세부 항목 57개**와 구축·유지보수·운영·관제 등 **업무 14개**를 별도 축으로 분류합니다. 각 축은 복수 선택할 수 있습니다.

수집은 같은 축 안에서 하나라도 일치하고 선택한 축 사이에서는 모두 일치해야 합니다. 세부 항목이나 업무를 비우면 그 축은 제한하지 않습니다. 기본적으로 관련성이 확인된 공고만 첨부를 받고, 애매한 공고는 **판단 보류**에 제목·상세·원본 링크만 저장합니다. `애매한 공고도 첨부를 확인`을 켜면 누락을 줄이는 모드로 바뀝니다.

**분류 보류·추가 수집** 탭에서 보류 사유를 확인하고 직접 분류한 뒤 `수집 대상으로 확정`할 수 있습니다. 아래 대기 목록에서 원하는 공고만 선택하고 `선택한 확정 공고만 첨부 수집·분석`을 실행합니다. 다른 대기 건과 완료한 건은 건드리지 않습니다. 실패하면 재시도 대기에 남습니다. 수동 분류는 자동 결과로 덮어쓰지 않습니다.

관리자 화면의 **분류 사전 관리**에서 키워드·동의어 수정, 항목 추가·비활성화와 JSON 내보내기를 제공합니다. [기본 분류표와 조사 근거](.doc/design/features/설계서_분야솔루션업무분류.md)를 참고하세요.

HWP·HWPX(표 Markdown), PDF Markdown과 OCR, DOCX(문단 평문), PPTX·HTML·RTF(pandoc), XLSX·XLS(CSV), TXT를 읽습니다. Streamlit Cloud는 `packages.txt`로 pandoc·Tesseract를 설치합니다. 신청서·서약서·계약서(안)·별첨 서식·표준 입찰유의서는 분석에서 제외하고 화면의 추출 결과에 사유를 남깁니다. 확장자가 잘못된 파일은 실제 형식을 확인합니다. 파일 해시 기반 캐시를 재사용하며 실패·부분 성공 파일은 재시도합니다. PDF OCR은 텍스트가 부족한 페이지에만 적용합니다.

```bash
uv pip install --python .venv/bin/python -r requirements.txt
brew install tesseract tesseract-lang
```

한국어·영어 OCR에는 `kor`, `eng` 언어 데이터가 필요합니다. 암호화·손상·미지원 파일, 첨부 없는 공고는 원본 확인 상태로 표시합니다. 농협정보시스템 등에서 외부 전자구매 시스템을 안내하는 경우 공개 상세 접근과 첨부 접근을 구분합니다. 로그인·투찰은 자동화하지 않습니다.

문서 전체를 구간별로 읽고 결과를 통합합니다. 마감일·자격 등에는 원문 인용을 검증하며 근거가 없으면 `확인 불가`로 표시합니다. LLM 결과의 최종 확인은 원본 문서로 진행하세요.

## 기존 자료와 R2

사용자의 초기화 요청으로 기존 수집 공고·첨부·관련 캐시·백업은 삭제했습니다. 연결·사이트 설정과 합성 모델 비교 결과는 보존했습니다. 이후 수집한 공고의 찜·진행 상태와 수동 분류는 재처리해도 보존합니다. `기존 공고 문서 재추출·분류`는 기존 요약을 바꾸지 않으며 `선택 분야 기존 공고 재분석`에서 분석을 갱신할 수 있습니다. 새 수집은 완료한 공고를 건너뛰고, `기존 공고의 첨부도 새로 확인`으로 재수집할 수 있습니다.

R2는 기본적으로 꺼져 있습니다. 활성화한 뒤 명시적 업로드 버튼으로 로컬 DB와 첨부를 동기화합니다. 페이지 갱신으로 원격 DB를 자동 다운로드하지 않습니다. 백업·캐시·비밀 파일은 업로드 대상에서 제외합니다. 기존 관리자 상태 변경·삭제 기능은 R2 활성화 시 원격 동기화도 수행합니다.

## CLI와 검사

```bash
.venv/bin/python main.py --site KB국민은행 --mode 로컬 --categories 인프라 --solutions 서버 --work 유지보수
.venv/bin/python main.py --site 농협정보시스템 --mode 혼합 --budget 1
.venv/bin/python main.py --backfill
.venv/bin/python main.py --reanalyze --categories 보안,인프라 --budget 1
.venv/bin/python -m unittest discover -s tests
```

[설계서](.doc/design/features/설계서_입찰정보수집분석시스템.md)에 처리 흐름과 호환 정책을 기록했습니다. 로컬 실행 자료와 검증 결과는 Git에서 제외한 `data/`에 저장합니다.
