# 문서 파서 고수준 엔진 전환

날짜: 2026-10-31

## 결정
LLM 입력에서 표 구조를 보존하려고 `hwp_parser.py`의 포맷별 추출 엔진을 바꾼다. 공개 함수와 결과 형식(`status/method/segments/errors/text/hash`)은 유지한다.

| 형식 | 이전 | 이후 |
|---|---|---|
| PDF | pypdf 텍스트 + 직접 렌더링 OCR | `pymupdf4llm==1.28.2` 페이지별 Markdown, 내장 Tesseract OCR(`kor+eng`) |
| DOCX·PPTX·HTML | DOCX XML 문단만 | `pandoc -t gfm` |
| XLSX·XLS | XLSX XML 탭 구분, XLS 미지원(HWP로 오판) | `pandas` 시트별 CSV |
| HWPX | XML 문단(표 셀 평문) | 기존 XML 파서에 표 Markdown 렌더링 추가 |
| HWP | olefile 문단 레코드 | 유지 |

## 채택하지 않은 것
- `pyhwp2md` 0.1.3: 검증해 보니 HWPX는 표를 본문 뒤로 몰아 출력하고 섹션마다 표가 중복됐다. HWP는 내부적으로 `hwp5txt` 평문을 먼저 써서 표가 복원되지 않는다. 또한 AGPL `pyhwp`(Python 3.8 표기)에 의존한다.
- `pymupdf4llm` 2.0: 코드가 없는 빈 패키지다(pymupdf 2.x로 흡수됨). 현재 pymupdf 1.28.2에 맞춰 1.28.2로 고정한다.

## 영향
- 캐시 키 `PARSER_VERSION`을 5로 올려 기존 평문 캐시를 무효화한다.
- 시스템 바이너리 `pandoc`, `tesseract`(+`kor`)가 필요하다. Streamlit Cloud는 `packages.txt`로 설치한다.
- `pymupdf4llm`, `pymupdf-layout`은 PyMuPDF와 같은 AGPL 계열 라이선스다.
