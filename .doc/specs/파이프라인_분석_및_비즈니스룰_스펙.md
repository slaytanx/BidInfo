# 파이프라인 분석 및 비즈니스 룰 명세서 (Pipeline, Analysis & Business Rules Specification)

최신 업데이트: 2026-11-11

본 문서는 첨부 문서 텍스트 추출, OCR 처리 기준, 3축 분류 체계, 대형 언어 모델(LLM) 기반 심층 분석, RFP 원페이지 리포트·서류 질의응답(Q&A), 연도 롤오버 날짜 계산 및 실시간 UI 피드백 계약의 세부 규격을 정의합니다.

## 1. 문서 파서 및 OCR 엔진 명세 (Document Parser & OCR)

### 1.1. 포맷별 고수준 파싱 엔진 매핑

| 파일 확장자 | 사용 엔진 / 라이브러리 | 출력 형태 및 세부 처리 규격 |
| :--- | :--- | :--- |
| **PDF** | `pymupdf` (2.x) | 페이지별 Markdown 구조화 텍스트 (내장 표 마크다운 변환 포함). 텍스트 밀도 부족 페이지에 한해 Tesseract OCR 결합 |
| **HWP** | `olefile` + 바이너리 파서 | HWP 5.x 바이너리 레코드 파싱. 표(TABLE/77) 및 셀(LIST_HEADER/72) 좌표를 추적하여 Markdown 표로 복원 |
| **HWPX** | `zipfile` + `xml.etree` | Open Ant XML 표준. 원문 문단 순서 보존 및 표 엘리먼트 Markdown 표 변환 |
| **DOCX** | `zipfile` + `xml.etree` | Word XML 문단 평문 순차 추출 (`mc:Fallback` 중복 제거, 표 셀 텍스트 연속성 보존) |
| **XLSX / XLS** | `pandas`, `openpyxl`, `xlrd` | 각 시트(Sheet)별 CSV 포맷 변환 후 상단 헤더 연결 |
| **PPTX / RTF / HTML** | `pandoc` (`--to=gfm`) | GitHub Flavored Markdown 평문 변환 |
| **구형 OLE DOC** | 거부 필터 | 보안 및 신뢰성 한계로 'DOCX 변환 필요' 사유 명시 후 안전 거부 |

### 1.2. 비IT 및 단순 서식 자동 제외 비즈니스 룰 (`skip_reason`)
사업 내용이나 기술 요구사항이 없는 단순 행정 문서는 AI 분석 입력에서 조기 제외하여 LLM 환각(Hallucination) 및 토큰 낭비를 원천 차단합니다:
* **제외 대상**: 신청서, 청렴계약서, 입찰참가서약서, 보안서약서, 개인정보동의서, 표준 계약서(안), 별첨 서식, 순수 입찰유의서.
* **보호 규칙 (Whitelist)**: 파일명에 `공고`, `제안요청`, `RFP`, `사양`, `명세`가 포함된 문서는 서약서 키워드가 있더라도 **절대 제외하지 않고 분석 대상에 유지**.

### 1.3. OCR 트리거 조건 및 파라미터
* **엔진**: Tesseract OCR (`kor+eng` 언어팩)
* **트리거 조건**: PDF 페이지 내 추출된 유효 텍스트가 기준치 미만이거나 이미지 스캔본으로 판정될 때에만 선별적으로 OCR 파이프라인 가동.
* **캐시 관리**: `data/cache/documents/` 디렉터리에 `SHA-256(파일내용 + PARSER_VERSION('9') + OCR설정)` 해시 키로 저장.

## 2. 3축 택소노미 및 분류 상태 머신

### 2.1. 3축 분류 체계 (3-Axis Taxonomy)
1. **1축 (분야 / Domain)**: `인프라`, `보안`, `컨설팅`, `개발`, `기타` (기본 수집 대상은 인프라·보안·컨설팅·개발 4개)
2. **2축 (세부 항목 / Solution)**: 예) `서버`, `스토리지`, `네트워크`, `방화벽`, `IPS`, `EDR`, `XDR`, `DBMS` 등 **57개** 표준 솔루션 (인프라 18 · 보안 26 · 컨설팅 6 · 개발 7)
3. **3축 (업무 / Work)**: `구축`, `재구축`, `고도화`, `도입/구매`, `교체/증설`, `유지보수`, `운영`, `관제`, `진단/점검`, `설계/기획`, `전환/이전`, `개발`, `검증/시험`, `교육` (**14개**)

### 2.2. 매칭 및 필터링 로직 (`should_collect`)
* **동일 축 내부**: OR 조건 (선택된 항목 중 하나라도 일치하면 충족)
* **축 간 관계**: AND 조건 (선택된 모든 축의 조건을 동시에 충족해야 최종 수집 대상으로 확정)

### 2.3. 분류 상태 머신 (Classification State Machine)

```
[웹 공고 발견]
       │
       ▼
 1차 규칙 분류 ──(명백한 비IT)──> [수집 제외]
       │
   (IT 관련)
       │
       ├──(확실함)────────────> [자동] ──> (첨부 수집 및 AI 분석)
       │
       └──(불확실함)──────────> [판단 보류] (공고 메타데이터만 저장)
                                    │
                              (사용자 수동 개입)
                                    ▼
                         [수동 분류] / [수집 대기]
```

* **수동 확정 보호**: 사용자가 UI에서 수정한 `manual_classification`은 향후 크롤러 재실행 시에도 자동 분류 결과로 덮어쓰지 않고 최우선 보존됩니다.

## 3. 다중 LLM 심층 분석 명세 (LLM Analysis Specification)

### 3.1. 엔진 구성 및 동시성 제어
* **기본 추천 조합**:
  * 1차 클라우드 모델: OpenRouter `deepseek/deepseek-v4-flash-0731`
  * 2차 로컬 폴백 모델: Local Ollama `nemo-bolt:fast` 또는 `gemma4:26b-mlx`
* **동시성 세마포어**:
  * 로컬 Ollama 호출: 최대 **1건** (`_LOCAL_LOCK = threading.Semaphore(1)`) — 메모리 폭주 방지
  * OpenRouter 클라우드 호출: 최대 **2건** (`_CLOUD_LOCK = threading.Semaphore(2)`)
* **지수 백오프 및 헤더 파싱**:
  * OpenRouter 호출 시 429/500/502/503/504 에러 발생 시 `Retry-After` 헤더 값을 파싱하여 1회 재시도(`min(5.0, max(1.0, float(retry_after)))`).

### 3.2. JSON 파싱 내결함성 (`parse_json`)
* **마크다운 코드 블록 제거**: `r'```(?:json)?\s*([\s\S]*?)\s*```'` 정규식을 통해 JSON 문자열만 정밀 발췌.
* **서두 설명문(Preamble) 자동 회피**:
  모델이 서두에 "다음은 JSON 응답입니다:" 등의 안내 문구를 붙이는 경우, 첫 번째 `{`와 마지막 `}` 사이의 슬라이스를 취하여 JSON 파싱 성공률을 100% 보장.

### 3.3. 대용량 문서 청킹 및 항목별 추출 (Chunking & Grouped Fact Extraction)
1. **구간 분할 (Chunking)**:
   * 문서 전체 텍스트를 9,000자 단위(`document_chunks(text, size=9000)`)로 분할하여 구간별 분석 수행 후 요약·적합도·태그를 코드로 병합.
2. **3대 그룹 항목별 추출 (Grouped Extraction)**:
   * **그룹 1 (마감/제출)**: `['deadline', 'submit_type']`
   * **그룹 2 (서류/자격)**: `['required_docs', 'qualifications']`
   * **그룹 3 (예산/기간/평가)**: `['budget', 'duration', 'evaluation']`
   * 각 그룹별 관련 키워드가 포함된 문맥만을 정밀 발췌하여 LLM에 질의.

### 3.4. 인용 검증 및 사실 필터링 규격 (Quote Grounding & Fact Rejection)
* **원문 인용 필수 (Grounding)**:
  LLM이 추출한 사실(`fact`)은 반드시 원문에 존재하는 인용문(`quote`)과 매핑되어야 합니다. 원문에서 인용문을 찾을 수 없으면 해당 사실은 버리고 `"근거 미확인"` 또는 `"확인 불가"`로 강제 전환합니다.
* **형식 유효성 검사 (Format Validation)**:
  * `deadline`, `duration`: 실제 날짜나 숫자 표현(`\d`)이 포함되지 않은 모호한 답변("협의에 따름", "추후 결정" 등)은 거부.
  * `budget`: 금액 표현(숫자 + 원, 억원, 만원 등)이 없는 답변은 거부.
* **점수 및 스키마 검증 (`validate_analysis`)**:
  * `fit_score`: 반드시 0~100 사이의 정수.
  * 필수 11개 필드(`FIELDS`) 타입 및 JSON 형식 검증 통과 필수.

## 4. RFP 원페이지 리포트 및 서류 질의응답 (One-Page RFP & Q&A)

### 4.1. RFP 원페이지 리포트 (`generate_rfp_one_pager`)
* **목적**: 단일 공고의 첨부 문서 전체를 한눈에 파악할 수 있는 원페이지 요약 리포트 생성.
* **호출**: UI 탭 2(상세 리포트)에서 선택한 공고에 대해 `generate_rfp_one_pager(title, doc_text, engine_configs)` 호출.
* **출력**: 사업 개요, 핵심 요건, 평가 기준, 제출 서류, 마감 일정 등을 구조화된 마크다운 한 페이지로 생성.
* **모델**: 현재 선택된 엔진 구성(`engine_configs`)을 사용하며, 로컬·클라우드 폴백 로직을 공유.

### 4.2. 서류 질의응답 (`answer_bid_question`)
50~100페이지에 달하는 대용량 RFP 문서의 경우 전체 청크(10~20개)를 모두 호출하면 LLM 응답 지연과 토큰 낭비가 심각합니다:
* **질문 키워드 랭킹**:
  * 사용자 질문에서 2글자 이상의 의미 있는 단어를 추출 (`re.findall(r'[가-힣A-Za-z0-9]+', question)`).
  * 각 9,000자 청크 내 키워드 출현 빈도를 점수화하여 상위 **최대 3개 청크**만 선별 질의.
  * 검색된 청크가 없을 경우 기본 상위 2개 청크(개요/목차 구간)에 질의.
  * 청크가 3개 이하이면 필터링 없이 전체 청크에 질의.
* **원문 근거 보증**:
  * 답변 생성 시 해당 청크 내에 실제로 존재하는 인용문(`quote`)과 위치(`location`)이 함께 매핑된 근거만을 반환.
  * 첨부 문서가 없거나 추출에 실패한 경우 원본 확인 안내 메시지 반환.

## 5. 날짜 파싱 및 D-Day 연도 롤오버 보정 (`date_utils.py`)

* **연말 롤오버 보정 (`_adjust_year_rollover`)**:
  연도 표기가 생략된 월/일 마감일(예: `1월 15일 18:00`)이 연말(10~12월) 공고에서 발견될 경우, 단순 당해 연도로 계산하면 과거 일자(`D+300, 마감됨`)로 오판단되는 결함 방지:
  $$\text{year} = \begin{cases} \text{ref\_date.year} + 1 & \text{if } \text{ref\_date.month} \ge 10 \land \text{month} \le 3 \\ \text{ref\_date.year} & \text{otherwise} \end{cases}$$

## 6. 실시간 UI 피드백 계약 (UI Progress Feedback Contract)

대용량 문서(50~100페이지) 처리 시 정적 화면 멈춤을 방지하고 사용자 신뢰도를 높이기 위해 콜백 계약을 제공합니다:

* **콜백 함수 시그니처**:
  ```python
  def step_callback(item: dict, message: str) -> None:
      ...
  ```
* **단계별 표준 피드백 메시지**:
  1. `[공고제목...] 첨부 문서 추출 시작`
  2. `[공고제목...] 제안요청서.pdf 텍스트 추출 중... (15/45 페이지 OCR 진행)`
  3. `[공고제목...] 분야 및 솔루션 태그 판별 중`
  4. `[공고제목...] AI 심층 분석 시작 (1/3 구간 분석 중)`
  5. `[공고제목...] 핵심 사실(마감/예산/자격) 원문 인용 검증 중`
* **Streamlit 연동**: `st.status()` 블록 내부에서 상기 메시지를 실시간 렌더링하여 작업 완료 시 `expanded=False`로 접힘 처리.
