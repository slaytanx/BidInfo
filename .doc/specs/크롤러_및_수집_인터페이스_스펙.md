# 크롤러 및 수집 인터페이스 명세서 (Crawler & Collection Specification)

최신 업데이트: 2026-11-09

본 문서는 금융사 및 공공 조달 사이트의 입찰 공고 목록 조회, 본문 수집, 첨부파일 다운로드 프로토콜 및 네트워크 제어 명세를 정의합니다.

## 1. 네트워크 세션 및 보안 통신 인터페이스

### 1.1. 브라우저 TLS 위장 (Browser Impersonation)
* **엔진**: `curl_cffi.requests.Session(impersonate="chrome124")`
* **도입 목적**: 최신 금융권 및 전자조달 웹서버의 WAF/봇 탐지 및 SSL 핸드셰이크 필터링(JA3/JA4 지문 검사) 우회.
* **폴백 메커니즘**: `curl_cffi` 미설치 또는 환경 미지원 시 표준 `requests.Session`으로 자동 폴백.
* **예외 튜플 통합**: `(requests.RequestException, CffiRequestsError, CffiCurlError)`로 통일 처리.

### 1.2. 호스트별 트래픽 제어 (Rate Limiting)
* **최소 요청 간격**: 동일 호스트(`_base_domain`) 대상 **최소 0.3초** 간격 보장.
* **동시성 락**: `threading.Lock()`을 사용하여 멀티스레드 환경에서도 도메인별 마지막 요청 시각(`_LAST_REQUEST`)을 엄격히 준수.

### 1.3. 지수 백오프 및 재시도 규격
* **재시도 대상 HTTP 상태 코드**: `429 Too Many Requests`, `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout`, 일시적 네트워크 타임아웃/연결 끊김.
* **`Retry-After` 헤더 파싱**:
  * 서버 응답에 `Retry-After` 헤더가 존재할 경우 파싱하여 대기 시간 반영 (`min(10.0, max(1.0, float(retry_header)))`).
  * 비정형 헤더 문자열 수신 시 기본 지수 백오프로 안전 폴백.
* **기본 백오프 산출식**:
  $$\text{wait\_time} = 1.5 \times 2^{\text{attempt}}$$
* **최대 재시도**: 3회 시도 후 지속 실패 시 `CrawlError` 발생.

## 3. 사이트별 정밀 핸들러 세부 사항

### 3.1. 신한DS (`shinhands.co.kr`)
* **비정형 HTML 구조 대응**:
  신한DS 웹페이지는 `<tr>...<tr>`과 같이 닫는 태그(`</tr>`)가 누락된 비정형 HTML 테이블 구조를 가집니다.
  이를 안전하게 파싱하기 위해 정규식 패턴 `r'<tr\b[^>]*>'` 기반으로 행을 분할하여 셀 데이터를 누락 없이 추출합니다.
* **공고 경로 정규화**:
  과거 경로인 `/insight/disclosure`로 요청이 인입될 경우 활성 경로인 `/insight/business-notice`로 자동 정규화합니다.

### 3.2. 하나금융TI (`tipartner.hanati.co.kr`)
* **전자구매 시스템 연동 (EMRO 솔루션)**:
  공개 입찰 공고 목록 및 상세 내용이 CSRF 보호된 엔드포인트에서 제공됩니다.
* **토큰 라이프사이클**:
  1. 진입점 `https://tipartner.hanati.co.kr/spLogin.do` HTML을 1차 호출하여 `_csrf` 파라미터 값을 추출.
  2. 목록 조회 시 `POST /sp/mn/bidding/bidNoticeLink.do` 페이로드에 `_csrf`를 포함하여 전송.
  3. 첨부파일 다운로드 시 `POST /sp/mn/bidding/upload/download.do`에 `{'id': att_id, '_csrf': csrf}`를 전송하여 파일 수집.

### 3.3. 기관명 자동 식별 (`extract_org_from_title`)
공고 제목의 텍스트 패턴을 기반으로 세부 계열사를 정밀 식별합니다:
* 패턴: `(하나증권|하나카드|하나금융TI|하나은행|신한투자증권|신한카드|신한DS|신한은행|농협정보시스템|NH농협은행|KB국민은행)`

## 4. 공고 필터링 및 중복 수집 방지 비즈니스 룰

1. **기간 필터 (Date Range Filtering)**:
   * 사용자가 지정한 `start_date` ~ `end_date` 범위를 엄격히 검사.
   * `reg_date`가 없는 행은 오늘 날짜로 임의 추정하지 않고 유효 날짜 확인 시에만 포함.
2. **중복 수집 스킵 (Deduplication)**:
   * DB의 고유 식별자 `source_key:source_id`를 사전 대조하여 이미 수집 완료된 공고는 네트워크 상세/첨부 수집 단계 이전에 조기 스킵.
3. **명백한 비IT 공고 조기 배제 (`NON_IT`)**:
   * 제목에 다음 키워드가 포함된 공고는 첨부파일 다운로드 및 LLM 분석을 수행하지 않고 즉시 제외 처리:
     `조경`, `화환`, `구내식당`, `식자재`, `명절선물`, `승강기`, `건물 청소`, `영업점 인테리어`, `건축공사`, `농약`, `비료`, `카페라운지`, `부산물`, `원피`, `부동산 매각`, `세무조정`, `세무자문`, `유전체분석`, `시약`, `쿨링조끼` 등.
4. **무한 루프 방지**:
   * 동일한 게시글 목록이 반복 반환되는 페이징 오류 감지 시 수집을 자동 종료(`pagination: '목록 반복 감지: 추가 페이지 확인 필요'`)하며 최대 수집 페이지(Max Pages) 제한 적용.
5. **수동 확정 공고 단독 수집 (`collect_confirmed_bid`)**:
   * 사용자가 UI에서 수동 확정한 공고는 일반 목록 수집 루프를 거치지 않고 해당 단일 공고에 대해서만 상세 본문 및 첨부파일 다운로드를 단독 수행.

## 5. 첨부파일 저장 및 안전성 규격

* **HTTP 헤더 파일명 복원 (`decode_http_filename`)**:
  * 웹 서버가 `Content-Disposition` 헤더에서 한글 파일명을 Latin-1로 오역하여 전송하는 경우, `latin1` 인코딩 후 `utf-8` 또는 `cp949`로 디코딩하여 깨진 한글 파일명을 정상 복원.
* **파일명 정제 (`sanitize_filename`)**:
  * OS 특수문자(`\/*?:"<>|`) 및 제어문자(`\x00-\x1f`)를 `_`로 치환.
  * 최대 파일명 길이: 160자 제한.
* **압축파일(ZIP) 해제 안전 규칙 (`extract_zip`)**:
  * **Path Traversal 방지**: 상위 경로 참조(`../`, `..\`)가 포함된 엔트리 차단.
  * **용량 제한**: 단일 파일 최대 150MB(`MAX_FILE_BYTES`), 압축 해제 총합 최대 500MB(`MAX_ZIP_BYTES`).
  * **압축 폭탄(Zip Bomb) 방지**: 압축 해제 비율(Uncompressed/Compressed ratio) 비정상 초과 시 차단.
