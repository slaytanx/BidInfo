# 분류 사전과 수동 추가 수집 검증

최신 업데이트: 2026-10-13

## 적용 결과

분야 4개와 기타, 세부 항목 57개, 업무 14개를 SQLite 분류 사전에 저장했습니다. 동의어·약어·띄어쓰기 변형은 항목 간 중복을 포함해 총 432건 등록했습니다. 키워드는 공식 기관·벤더 자료를 참고해 프로젝트 목적에 맞게 구성했으며 공식 산업분류와는 구분합니다. 관리자는 세부 항목·업무의 동의어를 수정하고 항목 추가·비활성화를 할 수 있습니다.

관련성이 확인된 공고만 첨부를 수집하는 모드를 기본으로 적용했습니다. 선택한 축 사이는 AND, 같은 축의 여러 선택은 OR로 판단합니다. 판단 보류 공고는 제목·상세·원본 링크·보류 사유만 저장합니다. 사용자가 수동 확정한 공고는 수집 대기에 들어가며, 선택한 확정 공고만 별도 다운로드·추출·분석합니다. 일반 수집은 수동 대기열을 실행하지 않고 자동 재분류는 수동 값을 덮어쓰지 않습니다. 실패한 건은 재시도 대기에 남습니다.

## 자동 검사와 로컬 모델

자동 테스트 38개가 통과했습니다. 기존 문서·비용·DB 검증에 세 축의 분류, 약어 경계, 웹방화벽 구분, 사전 수정·비활성화 보존, 세 축 필터, 수동 분류 보존, 보류 건의 다운로드·분석 차단, 선택 확정 건만 처리, 실패 대기 유지, 일반 수집의 대기열 보호, 검토 UI를 추가했습니다.

합성 PDF와 격리 DB로 선택한 확정 건의 실제 다운로드 응답 저장 → 문서 추출 → 모의 LLM 분석 → DB 저장 → 완료 상태 전환을 검증했습니다. 선택하지 않은 확정 건은 수집 대기에 그대로 남았으며 첨부가 생성되지 않았습니다.

로컬 E4B 모델은 합성 IPS·방화벽 구축/운영 공고를 약 2.09초에 보안 / 방화벽·IPS / 구축·운영·관제로 분류했습니다. 로컬 26B는 합성 IPS·방화벽 유지보수 RFP에서 새 세 축 JSON 분석에 성공했습니다. 이는 일부 합성 사례이며 실제 공고 분류 정확도 전체를 보장하지 않습니다. OpenRouter 실측은 키 미연결로 수행하지 않았습니다.

## 사용자 승인 초기화

기존 공고 69개와 관련 첨부·검증 자료·캐시·백업 153개 항목, 364개 파일(약 52.4MB)을 확인한 뒤 삭제했습니다. 별도 실제 수집 검증 폴더 2개도 삭제했습니다. SQLite 공고 테이블은 secure_delete와 VACUUM으로 정리했습니다. 현재 공고 0건, 다운로드 첨부 0개를 확인했습니다.

연결·사이트 설정, 로컬 모델, 코드, 합성 모델 비교 결과는 보존했습니다. 새 분류 사전은 DB와 `data/taxonomy_catalog.json`으로 관리합니다. 모든 수집 대상 공고의 초기화이며 모델이나 연결 설정의 삭제가 아닙니다. 이전 검증 기록은 초기화 전의 과거 결과로 구분했습니다.
