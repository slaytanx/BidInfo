# 입찰 분야·세부 항목·업무 분류

최신 업데이트: 2026-10-13

## 분류 원칙

분야는 인프라·보안·컨설팅·개발·기타로 구분합니다. 서버·IPS 같은 제품 또는 서비스 종류는 세부 항목으로, 구축·유지보수·운영·관제 같은 수행 행위는 업무 태그로 저장합니다. 한 공고는 각 축에 여러 태그를 가질 수 있습니다. 예를 들어 서버·방화벽 유지보수는 인프라·보안 / 서버·방화벽 / 유지보수입니다.

공식 기관·벤더 용어 자료를 참고한 프로젝트용 사전입니다. 공식 산업분류나 인증 범위를 그대로 대체하지 않습니다. 브랜드명만으로 분야를 단정하지 않으며 한글 동의어·영문 약어·띄어쓰기 변형을 같은 항목으로 묶습니다. 약어는 영문 단어 내부에서 일치하지 않게 검사합니다. 구축을 개발 분야로 자동 분류하지 않고, 웹방화벽을 일반 방화벽과 구분합니다.

## 수집과 판단 보류

같은 축의 여러 선택은 하나라도 일치하면 됩니다. 분야·세부 항목·업무 사이는 모두 충족해야 합니다. 세부 항목·업무를 비우면 해당 축을 제한하지 않습니다. 기본값은 관련성이 확인된 공고만 첨부를 받으며, 상세 확인 이후에도 선택 조건 일치를 확인하지 못한 불확실한 공고는 판단 보류로 저장합니다. 명백히 무관한 공고는 제외합니다. 제목만으로 애매하면 공개 상세를 조회할 수 있으며 첨부 다운로드와 LLM 상세 분석은 보류합니다.

애매한 공고도 첨부를 확인하는 옵션을 별도로 제공합니다. 관련 내용이 첨부 안에만 있으면 기본 모드에서 놓칠 수 있습니다. 분류는 자동 판단이며 실제 사업 범위는 원본으로 최종 확인합니다.

## 수동 확정과 추가 수집

판단 보류 목록에서 제목·원본 링크·보류 사유·상세 텍스트를 보고 분야·세부 항목·업무를 수동 지정합니다. 수집 대상으로 확정하면 수집 대기가 되고, 수집 제외로 지정하면 자동 수집 대상에서 제외됩니다. 수동 값은 자동 재분류나 분석으로 덮어쓰지 않습니다.

선택한 확정 공고만 첨부 수집·분석 버튼은 선택한 수집 대기 ID만 실행합니다. 공고 목록이나 다른 확정 건을 다시 수집하지 않습니다. 일반 수집 버튼도 수동 대기열을 자동 실행하지 않습니다. 성공한 건은 수동 분류로 전환해 다음 대기 목록에서 빠지고, 첨부 없음·다운로드 또는 분석 실패는 수집 대기에 남겨 재시도할 수 있습니다.

## DB와 관리 화면

`taxonomy` 테이블에 구분·소속 분야·이름·동의어·활성 여부·참고 자료를 저장합니다. 기본 항목은 최초 삽입만 수행하므로 수정한 동의어나 비활성화 상태를 재시작으로 되돌리지 않습니다. 관리자는 기존 항목의 동의어와 활성 여부를 수정하고 세부 항목·업무를 추가할 수 있습니다. 기존 분류를 보존하기 위해 항목 이름·소속은 고정하며 삭제 대신 비활성화를 사용합니다.

공고의 `tags`는 상위 분야이며 `solution_tags`, `work_tags`를 분리합니다. `classification_status`, `manual_classification`, `notice_text`로 판단 보류와 수동 확정을 관리합니다. 기존 단일 태그는 `legacy_tags`로 보존하는 마이그레이션을 제공합니다. 사전 변경은 분석 캐시 식별자에 포함해 예전 분류를 재사용하지 않습니다.
